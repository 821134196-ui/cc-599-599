# 报刊亭期刊订阅到刊与缺刊补发系统

读者订阅连续刊期，报刊亭**逐期**记录履约（到刊 / 领取 / 缺刊 / 补发 / 退款），
而不是只看整份订阅是否完成。

- 后端：Go + Gin + GORM + SQLite（纯 Go 驱动，免 CGO）
- 前端：Vue 3（已本地化到 `static/`，无需联网、无需构建）
- 出版社回执：本地接口模拟

## 一条命令启动

```bash
go run .
```

打开 http://localhost:8080 —— 首页三个页签：**读者页 / 店员台 / 库存与刊期**。
首次启动自动建表并写入演示数据（`kiosk.db`）。

## 验证对账（合刊 / 重复回执 / 停刊退款）

```bash
go test ./...     # 单元级验证：期数、库存、金额
go run . demo     # 场景级对账演示，直接打印核对结果
```

`demo` 在内存库中完整跑一遍：

1. **合刊折算**：《都市生活月刊》签约规则为 7-8 月合刊计 2 期，
   全年 11 个物理刊期 = 12 个签约期数；合刊到货后履约期数一次 +2。
2. **幂等**：重复登记到货（同幂等键）、重复出版社回执（同回执号/同申请）、
   重复签收回执——库存与履约次数只变动一次。
3. **停刊退款**：按未履约期数 × 签约单价退款，逐期出明细；
   校验 `已付款 = 已履约金额 + 已退款 + 待结算`，重复停刊不重复退款。

## 业务规则

| 规则 | 实现 |
|---|---|
| 逐期履约 | 每份订阅 × 每个刊期一条履约记录（唯一索引），状态机：待到刊→已到刊→已领取；缺刊→待补发→已到刊(补发) |
| 合刊 | 刊期表 `counts_as` 折算（合刊=2），签约时快照到履约记录 |
| 补发 | 补发件归入**原期号**：不新增履约记录、不增加订阅期数、不重复计交付 |
| 重复登记 | 到货批次幂等键唯一；出版社回执号唯一；签收按状态幂等 |
| 停刊退款 | 未履约期数（未到刊的）× 签约单价 × 份数，逐期明细；每订阅最多一笔 |
| 取刊方式调整 | 只更新 `pending`（未来刊期）的快照，已到刊/已领取等保持原样 |

## 主要接口

```
GET  /api/subscriptions/:id/view     读者逐期视图（含汇总与退款明细）
POST /api/subscriptions              新订阅（按刊期表展开履约记录）
PUT  /api/subscriptions/:id/pickup-method  调整取刊方式（仅未来刊期）
POST /api/arrivals                   登记到货（幂等键）→ 自动分配/缺刊
POST /api/fulfillments/:id/pickup    签收（重复回执只计一次）
POST /api/fulfillments/:id/mark-missing       登记缺刊
POST /api/fulfillments/:id/reissue-requests   申请补发
POST /api/publisher/receipts         模拟出版社回执（补发件入原期号）
POST /api/publications/:id/suspend   停刊 → 生成退款（含明细，幂等）
GET  /api/inventories                刊期库存（到货/分配/领取/可分配）
```

环境变量：`KIOSK_DB`（默认 `kiosk.db`）、`KIOSK_ADDR`（默认 `:8080`）。
